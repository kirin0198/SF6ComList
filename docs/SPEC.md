## 1. プロジェクト概要

### 目的・背景

ストリートファイター6（SF6）のキャラクターごとのコンボを保存し、自分だけのコンボ帳を作成する個人向けWebサービス。ビジュアルUI（方向キーパッド + ボタンパレット）でコンボ入力コマンドを組み立て、キャラクター別・タグ別に整理・検索できる。

既存のコンボ管理ツール（ComboTier、sf6combo等）はコミュニティ共有型であり、「自分だけのコンボ帳」として個人管理に特化したサービスは少ない。本プロジェクトはビジュアルコンボ入力UI + 個人データ管理 + タグベース整理を組み合わせた差別化を実現する。

### 対象ユーザー

SF6プレイヤー（個人利用）。開発者自身が主なユーザーであり、日常的にコンボの記録・参照に使用する。

### PRODUCT_TYPE

service

### スコープ

- **IN（MVP）:**
  - メール/パスワード認証（ユーザー登録・ログイン・ログアウト）
  - キャラクター一覧表示（JSONマスタデータ、全30キャラクター）
  - コンボCRUD（登録・閲覧・編集・削除）
  - ビジュアルコンボ入力UI（方向キーパッド + ボタンパレット + コネクター + プレビュー）
  - テンキー表記テキスト入力モード
  - テンキー表記 <-> ビジュアル表示の相互変換
  - プリセットタグ（12種）+ ユーザー定義タグ
  - キャラクター別コンボ一覧表示
  - タグフィルタ
  - コンボへのダメージ値・メモ記録
  - ローカル環境（docker-compose）での動作
  - クラシック操作（6ボタン体系）のみ対応
- **OUT（MVPに含まない）:**
  - ソーシャルログイン（Google/GitHub OAuth） --- Phase 2
  - レスポンシブデザイン（スマホ最適化） --- Phase 2
  - コンボの並び替え（ダメージ順等） --- Phase 2
  - お気に入りピン留め --- Phase 2
  - モーションショートカットボタン（QCF, DP等） --- Phase 2
  - コンボの公開・共有機能 --- Phase 3
  - コンボのインポート・エクスポート --- Phase 3
  - フレームデータ連携 --- Phase 3
  - モダン操作対応 --- Phase 3
  - AWS/GCPへのデプロイ --- Phase 3

## 2. 推奨技術スタック

| 層             | 技術                                                 | 選定理由                                                                                                        |
| -------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| フロントエンド | Next.js (App Router) + React                         | PoCでReactコンポーネントの実装パターンが確立済み。APIルートによるバックエンド統合でモノリス構成が可能           |
| スタイリング   | Tailwind CSS                                         | PoCでボタン色分けの型安全な管理パターン（colorClass）が実証済み。ユーティリティファーストでカスタムUI構築に適合 |
| 言語           | TypeScript                                           | PoCの複雑な型定義（Direction Union型、ComboStep Discriminated Union等）を型安全に管理するために必須             |
| 認証           | Auth.js (NextAuth.js v5)                             | メール/パスワード認証を統一的に管理。将来のOAuth追加にも対応。ローカル環境でのlocalhost対応も問題なし           |
| ORM            | Prisma                                               | TypeScript対応のスキーマ駆動ORM。ComboのsequenceフィールドをJson型で格納可能                                    |
| DB（ローカル） | SQLite                                               | Docker不要で起動できる軽量DB。Prismaの抽象化により将来PostgreSQLへの移行が容易                                  |
| アイコン素材   | 自作SVG + Fighting Game Input Icons Pack (CC-BY-4.0) | PoCで確認したアイコンマッピング構造に基づく。著作権リスクを回避                                                 |

### 技術スタック選定の思考過程

**Step 1. 要件のドメインと特性:**

- Webアプリケーション（SPA + API）であり、ビジュアルコンボ入力UIという複雑なインタラクティブUIを含む
- 個人利用のためスループット要件は低い。型安全性と開発効率を優先すべき
- コンボデータの複雑なJSON構造（Union型、ネスト構造）を扱うため、型安全性が重要

**Step 2. ベストプラクティスの適用:**

- 複雑なインタラクティブUIを持つSPA → React がベストプラクティス
- フルスタックTypeScript → Next.js (App Router) がAPIルートとSSRを統合できる
- PoCで React + TypeScript の実装パターンが確立済みであり、技術的リスクが解消されている

**Step 3. プロジェクト固有の制約:**

- ユーザーは技術スタックの指定なし（「おまかせ」）
- PoCコード（combo-data-model.ts, notation-converter.ts, ComboInputUI.tsx, ComboDisplay.tsx）がTypeScript + Reactで実装済みであり、再利用可能
- ローカル環境前提のため、外部サービスへの依存を最小化すべき

**Step 4. 却下した代替案:**

- **FastAPI + React SPA（分離型）:** フロント/バック分離はデプロイ構成が複雑になる。Next.jsのモノリス構成の方がローカル環境で簡潔
- **Vue.js / Svelte:** PoCがReactで実装済みのため、移植コストが発生する。Reactのエコシステム（dnd-kit等）も活用可能
- **PostgreSQL（初期から）:** ローカル開発ではDocker依存が増える。SQLiteの方が起動が軽量で、Prisma経由で後からPostgreSQLに移行可能

> ※ 最終的な技術スタックは architect にて確定・詳細化する

## 4. 機能要件

### UC-001: ユーザー登録

- **概要:** 新規ユーザーがメールアドレスとパスワードでアカウントを作成する
- **事前条件:** ユーザーが未登録状態であること
- **正常フロー:**
  1. ユーザーが登録画面にアクセスする
  2. メールアドレスとパスワード（+ パスワード確認）を入力する
  3. システムが入力値をバリデーションする
  4. パスワードをハッシュ化してユーザーレコードを作成する
  5. 登録完了後、自動的にログイン状態になりキャラクター一覧画面へ遷移する
- **例外フロー:**
  - E1: メールアドレスが既に登録済み → エラーメッセージ「このメールアドレスは既に登録されています」を表示
  - E2: パスワードが要件を満たさない → エラーメッセージ「パスワードは8文字以上で入力してください」を表示
  - E3: パスワードと確認が一致しない → エラーメッセージ「パスワードが一致しません」を表示
- **受け入れ条件:**
  - AC1: 有効なメールアドレスとパスワード（8文字以上）で登録できること
  - AC2: パスワードがハッシュ化されてDBに保存されること（平文で保存されないこと）
  - AC3: 登録済みメールアドレスでの重複登録が拒否されること
  - AC4: 登録後に自動ログインされキャラクター一覧画面へ遷移すること

### UC-002: ログイン

- **概要:** 登録済みユーザーがメールアドレスとパスワードでログインする
- **事前条件:** ユーザーが登録済みであること
- **正常フロー:**
  1. ユーザーがログイン画面にアクセスする
  2. メールアドレスとパスワードを入力する
  3. システムが認証を検証する
  4. セッションを作成し、キャラクター一覧画面へ遷移する
- **例外フロー:**
  - E1: メールアドレスまたはパスワードが不正 → エラーメッセージ「メールアドレスまたはパスワードが正しくありません」を表示（どちらが不正かは明示しない）
- **受け入れ条件:**
  - AC1: 正しい認証情報でログインできること
  - AC2: ログイン後にセッションが維持されること（ブラウザリロードしてもログイン状態が保持される）
  - AC3: 不正な認証情報でログインが拒否されること
  - AC4: ログイン・登録画面への相互リンクがあること

### UC-003: ログアウト

- **概要:** ログイン中のユーザーがログアウトする
- **事前条件:** ユーザーがログイン状態であること
- **正常フロー:**
  1. ユーザーがログアウト操作を行う
  2. セッションが破棄される
  3. ログイン画面へ遷移する
- **例外フロー:** なし
- **受け入れ条件:**
  - AC1: ログアウト後にセッションが無効化されること
  - AC2: ログアウト後にログイン画面へ遷移すること
  - AC3: ログアウト後にブラウザの戻るボタンで認証が必要な画面にアクセスできないこと

### UC-004: キャラクター一覧表示

- **概要:** SF6の全キャラクター一覧を表示し、コンボを管理したいキャラクターを選択する
- **事前条件:** ユーザーがログイン状態であること
- **正常フロー:**
  1. キャラクター一覧画面にアクセスする
  2. 全30キャラクターがグリッド表示される（キャラクター名 + アイコン + 登録コンボ数）
  3. キャラクターをクリックすると、そのキャラクターのコンボ一覧画面（UC-007）へ遷移する
- **例外フロー:**
  - E1: キャラクターデータの読み込み失敗 → エラーメッセージを表示しリトライを促す
- **受け入れ条件:**
  - AC1: 全30キャラクター（active ステータスのみ）が一覧表示されること
  - AC2: 各キャラクターに登録済みコンボ数が表示されること
  - AC3: キャラクターをクリックしてコンボ一覧に遷移できること
  - AC4: upcoming ステータスのキャラクター（未リリース）は一覧に表示されないこと

### UC-005: コンボ登録（ビジュアル入力）

- **概要:** ビジュアルUIを使ってコンボを組み立て、保存する
- **事前条件:** ユーザーがログイン状態で、キャラクターが選択されていること
- **正常フロー:**
  1. コンボ登録画面にアクセスする
  2. ビジュアル入力モードで方向キーパッドから方向を選択する（複数選択可: 236など）
  3. ボタンパレットからボタンを選択してステップを確定する
  4. コネクター（>, xx, ~, ,）を選択して次のステップとの接続を指定する
  5. 手順2〜4を繰り返してコンボを完成させる
  6. プレビュー領域でコンボの見た目とテンキー表記テキストをリアルタイム確認する
  7. コンボ名（任意）、ダメージ値（任意）、メモ（任意）、タグを入力する
  8. 保存ボタンを押すとコンボが登録される
- **例外フロー:**
  - E1: コンボシーケンスが空の状態で保存しようとした → 保存ボタンが非活性
  - E2: ネットワークエラーで保存に失敗 → エラーメッセージを表示し入力内容を保持する
- **受け入れ条件:**
  - AC1: 方向キーパッド（3x3テンキー配置）で9方向全てが選択できること
  - AC2: ボタンパレットで6ボタン（LP/MP/HP/LK/MK/HK）+ ドライブアクション（DI/DR/DP/OD/DRev）+ SA（SA1/SA2/SA3）+ Throw が選択できること
  - AC3: コネクター（>, xx, ~, ,）が選択できること
  - AC4: ODトグルでOD技を入力できること
  - AC5: プレビュー領域にリアルタイムでコンボが表示されること
  - AC6: テンキー表記テキストがリアルタイムで生成・表示されること
  - AC7: 「元に戻す」で最後の入力を取り消せること
  - AC8: 「リセット」で全入力をクリアできること
  - AC9: 保存後にキャラクター別コンボ一覧へ遷移すること

### UC-006: コンボ登録（テンキー表記テキスト入力）

- **概要:** テンキー表記のテキストを直接入力してコンボを登録する
- **事前条件:** ユーザーがログイン状態で、キャラクターが選択されていること
- **正常フロー:**
  1. コンボ登録画面でテキスト入力モードに切り替える
  2. テンキー表記テキスト（例: `5MP > 2MK xx 236HP`）を入力する
  3. システムがリアルタイムでビジュアルプレビューに変換・表示する
  4. コンボ名（任意）、ダメージ値（任意）、メモ（任意）、タグを入力する
  5. 保存ボタンを押すとコンボが登録される
- **例外フロー:**
  - E1: パースできない表記が含まれる → 該当部分をハイライトし警告表示する
  - E2: テキストが空の状態で保存しようとした → 保存ボタンが非活性
- **受け入れ条件:**
  - AC1: テンキー表記テキストを入力できるテキストフィールドがあること
  - AC2: 入力と同時にビジュアルプレビューに変換されること
  - AC3: パースエラー時にユーザーに警告が表示されること
  - AC4: ビジュアル入力モードとテキスト入力モードを切り替えできること
  - AC5: テキスト入力内容がビジュアル入力モードに反映される（相互変換）こと

### UC-007: キャラクター別コンボ一覧表示

- **概要:** 選択したキャラクターに紐づくコンボの一覧を表示する
- **事前条件:** ユーザーがログイン状態で、キャラクターが選択されていること
- **正常フロー:**
  1. キャラクターのコンボ一覧画面にアクセスする
  2. そのキャラクターに登録された全コンボがリスト表示される
  3. 各コンボにはコンボ名、ビジュアル表記、テンキー表記、ダメージ値、タグが表示される
  4. コンボ登録ボタン（新規追加）が表示される
- **例外フロー:**
  - E1: コンボが1件も登録されていない → 「コンボが登録されていません。最初のコンボを登録しましょう」と表示し、登録画面へのリンクを提供
- **受け入れ条件:**
  - AC1: ログインユーザー自身のコンボのみが表示されること（他ユーザーのコンボは表示されない）
  - AC2: 各コンボのビジュアル表記（アイコン列）が表示されること
  - AC3: 各コンボのテンキー表記テキストが表示されること
  - AC4: ダメージ値が設定されているコンボにはダメージ値が表示されること
  - AC5: タグが設定されているコンボにはタグがバッジとして表示されること
  - AC6: コンボ登録画面への導線があること

### UC-008: コンボ詳細表示

- **概要:** 登録済みコンボの詳細情報を表示する
- **事前条件:** ユーザーがログイン状態で、コンボが存在すること
- **正常フロー:**
  1. コンボ一覧からコンボを選択する
  2. コンボの詳細情報（コンボ名、ビジュアル表記、テンキー表記、ダメージ値、タグ、メモ、作成日、更新日）が表示される
  3. 編集・削除ボタンが表示される
- **例外フロー:**
  - E1: 他ユーザーのコンボにアクセスしようとした → 404画面を表示する
- **受け入れ条件:**
  - AC1: コンボの全属性（名前、シーケンス、ダメージ、タグ、メモ、日時）が表示されること
  - AC2: ビジュアル表記が大きく見やすいサイズで表示されること
  - AC3: 編集画面への導線があること
  - AC4: 削除操作が可能であること

### UC-009: コンボ編集

- **概要:** 登録済みコンボの内容を修正する
- **事前条件:** ユーザーがログイン状態で、自分のコンボであること
- **正常フロー:**
  1. コンボ詳細画面またはコンボ一覧から編集操作を行う
  2. 編集画面にコンボの現在の内容がプリセットされた状態で表示される
  3. ビジュアル入力またはテキスト入力でコンボシーケンスを修正する
  4. コンボ名、ダメージ値、メモ、タグを修正する
  5. 保存ボタンを押すと変更が反映される
- **例外フロー:**
  - E1: 他ユーザーのコンボを編集しようとした → 403エラーを返す
  - E2: 保存に失敗 → エラーメッセージを表示し編集内容を保持する
- **受け入れ条件:**
  - AC1: 既存のコンボデータが編集フォームにプリセットされること
  - AC2: コンボシーケンス・名前・ダメージ・メモ・タグの全てが編集可能であること
  - AC3: 保存後にupdatedAtが更新されること
  - AC4: 自分以外のコンボは編集できないこと

### UC-010: コンボ削除

- **概要:** 不要なコンボを削除する
- **事前条件:** ユーザーがログイン状態で、自分のコンボであること
- **正常フロー:**
  1. コンボ詳細画面またはコンボ一覧から削除操作を行う
  2. 確認ダイアログ「このコンボを削除しますか？（この操作は取り消せません）」を表示する
  3. ユーザーが確認すると、コンボがDBから削除される
  4. コンボ一覧画面へ遷移する
- **例外フロー:**
  - E1: 他ユーザーのコンボを削除しようとした → 403エラーを返す
  - E2: ユーザーがキャンセルした → 元の画面に留まる
- **受け入れ条件:**
  - AC1: 削除前に確認ダイアログが表示されること
  - AC2: 確認後にコンボがDBから物理削除されること
  - AC3: 削除後にコンボ一覧画面へ遷移すること
  - AC4: 自分以外のコンボは削除できないこと

### UC-011: タグフィルタ

- **概要:** コンボ一覧をタグで絞り込む
- **事前条件:** ユーザーがログイン状態で、キャラクターのコンボ一覧画面にいること
- **正常フロー:**
  1. コンボ一覧画面でタグフィルタ領域を操作する
  2. プリセットタグまたはユーザー定義タグを選択する（複数選択可）
  3. 選択したタグのいずれかを持つコンボのみが一覧に表示される（OR条件）
  4. フィルタを解除すると全コンボが表示される
- **例外フロー:**
  - E1: 選択したタグに該当するコンボがない → 「該当するコンボがありません」と表示
- **受け入れ条件:**
  - AC1: プリセットタグ12種がフィルタ選択肢に表示されること
  - AC2: ユーザー定義タグもフィルタ選択肢に表示されること
  - AC3: 複数タグを選択した場合、OR条件で絞り込みが行われること
  - AC4: フィルタの解除（全コンボ表示への復帰）が可能であること
  - AC5: フィルタ結果が即座に反映されること（ページリロード不要）

### UC-012: ユーザー定義タグ作成

- **概要:** ユーザーが独自のタグを作成する
- **事前条件:** ユーザーがログイン状態であること
- **正常フロー:**
  1. コンボ登録・編集画面のタグ入力欄で新しいタグ名を入力する
  2. 既存タグに一致しない場合、新規タグとして作成される
  3. 作成されたタグがコンボに紐づけられる
- **例外フロー:**
  - E1: タグ名が空 → タグは作成されない
  - E2: 同名のタグが既に存在する → 既存タグを使用する（重複作成しない）
- **受け入れ条件:**
  - AC1: 任意のテキストでタグを作成できること
  - AC2: タグ名は1〜30文字であること
  - AC3: 同名のタグが重複作成されないこと
  - AC4: ユーザー定義タグはそのユーザーのみに表示されること（プリセットタグは全ユーザー共通）

> 更新: 2026-04-12 (ISSUE-001: コマンドリスト入力モード追加)

### UC-013: コンボ登録（コマンドリスト入力）

- **概要:** キャラクター固有のコマンドリスト（必殺技・特殊技・ターゲットコンボ等）から技を選択してコンボを組み立てる
- **事前条件:** ユーザーがログイン状態で、キャラクターが選択されていること
- **正常フロー:**
  1. コンボ登録画面にアクセスする（デフォルトでコマンドリスト入力モードが表示される）
  2. キャラクターのコマンドリストがカテゴリ別（通常技・特殊技・必殺技・SA・投げ・ドライブ系・ターゲットコンボ）に表示される
  3. コマンドリストから技をクリックすると、対応するコンボステップがシーケンスに追加される
  4. 既にステップがある場合はコネクター（デフォルト: `>`）が自動挿入される
  5. コネクターの種類は手動で変更可能（ConnectorSelector と同様の操作）
  6. 手順3〜5を繰り返してコンボを完成させる
  7. プレビュー領域でコンボの見た目とテンキー表記テキストをリアルタイム確認する
  8. コンボ名（任意）、ダメージ値（任意）、メモ（任意）、タグを入力する
  9. 保存ボタンを押すとコンボが登録される
- **例外フロー:**
  - E1: 選択したキャラクターのコマンドリストデータが未登録の場合 → 「このキャラクターのコマンドリストは準備中です。ビジュアル入力またはテキスト入力をご利用ください。」と表示する
  - E2: コンボシーケンスが空の状態で保存しようとした → 保存ボタンが非活性
- **受け入れ条件:**
  - AC1: コマンドリスト入力モードがデフォルトの入力タブとして表示されること
  - AC2: キャラクター固有のコマンドリスト（必殺技・特殊技・SA・ターゲットコンボ等）がカテゴリ別に表示されること
  - AC3: 技名とテンキー表記が各技の行に表示されること
  - AC4: 技をクリックするとコンボシーケンスに追加されること
  - AC5: 既にステップがある場合はコネクターが自動挿入されること
  - AC6: コマンドリスト入力とビジュアル入力・テキスト入力の間でデータが相互変換されること
  - AC7: プレビュー領域にリアルタイムでコンボが表示されること
  - AC8: コマンドリストデータが未登録のキャラクターでは適切なメッセージが表示されること

## 5. 非機能要件

### パフォーマンス

- ページロード時間: 3秒以内（ローカル環境）
- コンボ一覧の表示: キャラクター1人あたり100件のコンボまでストレスなく表示可能
- ビジュアル入力UIのレスポンス: 方向キー・ボタンのクリックから50ms以内にプレビューに反映
- 同時接続数: 1〜数名（個人利用前提）

### セキュリティ

- パスワードはbcrypt等のハッシュアルゴリズムでハッシュ化して保存する
- XSS対策: ユーザー入力（コンボ名・メモ・タグ名）はエスケープ処理を行う
- CSRF対策: フォーム送信時にCSRFトークンを検証する
- ユーザーデータ分離: 各ユーザーは自分のコンボ・タグのみにアクセス可能。APIレベルで所有者チェックを行う
- セッション管理: HTTPOnly Cookieでセッションを管理する

### データ永続化

- サーバー側（SQLite）にデータを永続化する
- ログイン端末を問わずアクセス可能（ローカルネットワーク内）
- SQLiteファイルはdocker-composeのボリュームマウントで永続化する

### 可用性

- ローカル環境前提のため、高可用性は不要
- docker-composeによるワンコマンド起動を実現する

### 主要な関係性

```
User 1:N Combo       -- 1ユーザーが複数コンボを所有
Character 1:N Combo  -- 1キャラクターに複数コンボが紐づく（論理的参照）
Combo N:N Tag        -- コンボとタグは多対多（ComboTag中間テーブル経由）
User 1:N Tag         -- ユーザー定義タグはユーザーに紐づく（プリセットタグは共通）
```

### コンボシーケンスデータ構造（ComboSequence）

PoCで検証済みの型定義（`poc/combo-data-model.ts`）に基づく。DB上ではJSONカラムとして格納する。

```typescript
// コンボシーケンス全体
interface ComboSequence {
  steps: ComboStep[];
  notation: string; // テンキー表記文字列（表示・検索用）
}

// 1ステップ = 通常入力 | 溜め入力 | コネクター
type ComboStep = NormalInput | ChargeInput | ConnectorStep;

// 通常の方向+ボタン入力
interface NormalInput {
  type: "normal";
  directions: Direction[]; // テンキー方向: "1"〜"9"
  button: ButtonInput; // LP/MP/HP/LK/MK/HK/DI/DR/DP/PP/DRev/OD/SA1/SA2/SA3/Throw
  modifier?: AttackModifier; // j/cl/cr/st
  isOD?: boolean; // OD技の場合 true
}

// 溜め入力
interface ChargeInput {
  type: "charge";
  chargeDir: Direction; // 溜め方向 例: "4"
  releaseDir: Direction; // 離す方向 例: "6"
  button: BasicButton; // LP/MP/HP/LK/MK/HK
}

// コネクター
interface ConnectorStep {
  type: "connector";
  symbol: ">" | "xx" | "~" | ","; // リンク | キャンセル | ディレイ | 区切り
}
```

### 方向入力（Direction）

テンキー配置。キャラクターが右向き（1P側）を基準とする。

```
7(上後) 8(上)   9(上前)
4(後)   5(N)    6(前)
1(下後) 2(下)   3(下前)
```

### ボタン入力（ButtonInput）

| カテゴリ       | ボタン                   | 説明                                                                                                           |
| -------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| パンチ         | LP, MP, HP               | 弱・中・強パンチ                                                                                               |
| キック         | LK, MK, HK               | 弱・中・強キック                                                                                               |
| ドライブ       | DI, DR, DP, PP, DRev, OD | ドライブインパクト、ドライブラッシュ、ドライブパリィ、パーフェクトパリィ、ドライブリバーサル、オーバードライブ |
| スーパーアーツ | SA1, SA2, SA3            | スーパーアーツ1〜3（SA3 = Critical Art）                                                                       |
| その他         | Throw                    | 投げ（LP+LK）                                                                                                  |

## 9. ビジュアルコンボ入力UIの仕様

PoCで検証済みの実装パターン（`poc/ComboInputUI.tsx`）に基づく。

### コンポーネント構成

```
ComboInputUI（メインコンテナ）
  +-- ComboSequencePreview   // コンボのリアルタイムプレビュー（ビジュアル + テンキー表記テキスト）
  +-- DraftIndicator          // 方向選択中の状態表示（例: "方向選択中: 236 -> ボタンを選択して確定"）
  +-- DirectionPad            // 方向キーパッド（3x3テンキー配置）
  +-- ButtonPalette           // ボタンパレット（5グループ）
  +-- ConnectorSelector       // コネクター選択ボタン（>, xx, ~, ,）
  +-- ModifierControls        // 修飾子コントロール（ODトグル）
  +-- ActionButtons           // アクションボタン（元に戻す / リセット / 保存）
  +-- TextInputToggle         // テキスト入力モードへの切り替え
```

### 方向キーパッド（DirectionPad）

- 3x3グリッドでテンキー配置通りに9方向を表示する
- レイアウト:
  ```
  7(上後) 8(上)   9(上前)
  4(後)   5(N)    6(前)
  1(下後) 2(下)   3(下前)
  ```
- クリックするとドラフト状態に方向が追加される（複数選択可: 236 = 2 -> 3 -> 6）
- 各ボタンにはaria-labelで日本語方向名を設定する
- アイコンは自作SVG矢印（またはUnicode矢印文字をフォールバック）

### ボタンパレット（ButtonPalette）

5つのグループに分類して表示する。

| グループ       | ボタン               | 配色                                              |
| -------------- | -------------------- | ------------------------------------------------- |
| パンチ         | LP, MP, HP           | 青系（bg-blue-400, bg-blue-600, bg-blue-800）     |
| キック         | LK, MK, HK           | 赤系（bg-red-400, bg-red-600, bg-red-800）        |
| ドライブ       | DI, DR, DP, OD, DRev | 黄・緑・橙・紫系                                  |
| スーパーアーツ | SA1, SA2, SA3        | シアン系（bg-cyan-500, bg-cyan-600, bg-cyan-800） |
| その他         | Throw                | グレー系（bg-gray-500）                           |

- ボタンをクリックすると、ドラフトの方向 + このボタンで1ステップが確定する
- ドライブアクション（DI, DR等）やSA、Throwは方向なしでも単独で1ステップとなる

### コネクターセレクター（ConnectorSelector）

| ボタン | 記号 | 意味             |
| ------ | ---- | ---------------- |
| >      | >    | リンク（つなぎ） |
| xx     | xx   | キャンセル       |
| ~      | ~    | ディレイ / 派生  |
| ,      | ,    | コマンドの区切り |

- ステップ確定後にコネクターを選択して次のステップとの接続方法を指定する
- コネクターはステップ間に挿入される

### 操作フロー

1. **方向選択:** 方向キーパッドで方向を選択する（複数選択可）。選択中はドラフト状態として「方向選択中: 236」のように表示される
2. **ボタン選択でステップ確定:** ボタンパレットのボタンをクリックすると、ドラフトの方向 + ボタンで1ステップが確定し、プレビューに追加される
3. **コネクター追加:** 次のステップとの接続方法（>, xx, ~, ,）を選択する
4. **繰り返し:** 手順1〜3を繰り返してコンボを完成させる
5. **保存:** コンボが完成したら保存ボタンで確定する

### テキスト入力モード

- ビジュアル入力モードとテキスト入力モードを切り替えるトグルを提供する
- テキスト入力モードでは、テンキー表記文字列（例: `5MP > 2MK xx 236HP`）を直接入力する
- 入力と同時にビジュアルプレビューに変換される（`parseNotation()` 関数を使用）
- パースエラーが発生した場合、該当箇所を警告表示する
- モード切り替え時にデータが保持される（ビジュアル -> テキスト: serializeNotation、テキスト -> ビジュアル: parseNotation）

### 修飾子コントロール

- **ODトグル:** ON/OFFで切り替え。ONの場合、次に確定するステップが `isOD: true` になる
- 将来的にj./cr./st.等の修飾子トグルも追加可能（MVPでは方向入力で代替: j. = 7/8/9方向、cr. = 2方向）

## 11. 制約・前提条件

- ローカル環境（docker-compose）での動作が前提。インターネット公開は将来検討
- 個人利用が前提であり、大規模トラフィックは想定しない
- クラシック操作（6ボタン体系）のみ対応。モダン操作は将来検討
- キャラクターデータはJSONマスタデータによる手動管理。外部APIは使用しない
- キャラクターアイコンは自作SVGまたはプレースホルダーを使用する（CAPCOM公式画像は使用しない）
- アイコン素材のうち Fighting Game Input Icons Pack（CC-BY-4.0）を使用する場合はクレジット表記を行う
- 新規開発（既存システムとの統合なし）
- PoCコード（poc/ ディレクトリ）のロジック・型定義を本実装で再利用する

## 12. 用語集

| 用語                                  | 定義                                                                             | 備考                                      |
| ------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------- |
| コンボ (Combo)                        | 連続技。相手が反撃できない一連の攻撃入力のシーケンス                             | 本プロジェクトの主要管理対象              |
| テンキー表記 (Numpad Notation)        | 方向入力をPCテンキーの数字で表記する国際標準記法                                 | 本プロジェクトの基本表記法。FGCで広く採用 |
| BnB (Bread and Butter)                | 基本コンボ。最も頻繁に使う実用的な連続技                                         | プリセットタグの1つ                       |
| ドライブシステム (Drive System)       | SF6固有のリソース管理システム。6本のドライブゲージを消費して各種アクションを実行 | DI, DR, DP, DRev, OD の5種のアクション    |
| ドライブインパクト (DI)               | HP+HK同時押しで発動するアーマー付き攻撃。ドライブゲージ1本消費                   |                                           |
| ドライブラッシュ (DR)                 | パリィまたは通常技からキャンセルして前方にダッシュする行動                       | パリィから1本、キャンセルから3本消費      |
| ドライブパリィ (DP)                   | MP+MK長押しで発動する防御行動                                                    |                                           |
| パーフェクトパリィ (PP)               | 被弾2F以内にMP+MKで発動する精密な防御行動                                        |                                           |
| ドライブリバーサル (DRev)             | ガード中に6+HP+HKで発動する反撃行動。ドライブゲージ2本消費                       |                                           |
| オーバードライブ (OD)                 | 必殺技の強化版。同種ボタン2つ同時押しで発動。ドライブゲージ2本消費               | 旧作のEX技に相当                          |
| スーパーアーツ (SA)                   | スーパーアーツゲージを消費して発動する超必殺技。SA1, SA2, SA3の3段階             | SA3はCritical Artとも呼ばれる             |
| リンク (Link)                         | フレーム有利を利用して技をつなげること                                           | コネクター記号: >                         |
| キャンセル (Cancel)                   | 技のモーション中に別の技で割り込むこと                                           | コネクター記号: xx                        |
| パニッシュカウンター (Punish Counter) | 相手の技の隙に反撃でヒットさせた場合の特殊状態（+4F有利）                        | プリセットタグの1つ                       |
| カウンターヒット (Counter Hit / CH)   | 相手の攻撃動作中にヒットさせた場合の特殊状態（+2F有利）                          | プリセットタグの1つ                       |
| クラシック操作 (Classic)              | 従来のSFシリーズ準拠の6ボタン（LP/MP/HP/LK/MK/HK）操作体系                       | 本プロジェクトの基本対応操作              |
| モダン操作 (Modern)                   | 簡易入力の操作体系。ボタン数が少なくアシスト機能あり                             | 将来対応検討（Phase 3）                   |
| フレームデータ (Frame Data)           | 技の発生・持続・硬直等のフレーム（1/60秒）単位の数値情報                         | MVPスコープ外（Phase 3）                  |
| バーンアウト (Burnout)                | ドライブゲージが0になった状態。ドライブ関連アクションが使用不能になる            |                                           |
| FGC                                   | Fighting Game Community。格闘ゲームコミュニティ                                  |                                           |
